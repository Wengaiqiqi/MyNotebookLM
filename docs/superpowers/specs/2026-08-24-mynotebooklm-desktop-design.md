# MyNotebookLM Windows 桌面应用设计规格

日期：2026-08-24
状态：已批准

## 1. 产品目标

MyNotebookLM 是一款本地优先的 Windows AI 研究助手。用户通过标准 `.exe` 安装程序安装、升级和卸载应用，从开始菜单或桌面快捷方式启动，不需要打开浏览器、启动 Docker 或手动运行任何后端服务。

首个里程碑交付一条完整、可用的研究链路：

1. 创建研究项目。
2. 导入本地文件、网页或纯文本。
3. 在后台解析、分块并生成向量索引。
4. 使用全文与语义混合检索查找相关片段。
5. 选择本地或云端模型进行多轮问答。
6. 在回答中展示可定位到原始资料的引用。

应用数据默认保存在本机。只有用户选择云端生成模型或云端 Embedding 时，相关请求数据才会发送给对应服务商。选择云端 Embedding 后直接按配置处理，不显示额外弹窗或重复确认。

## 2. 首版范围

### 2.1 包含

- Windows x64 `.exe` 安装、覆盖升级和卸载。
- 简体中文与英文即时切换。
- 浅色与深色主题。
- 研究项目创建、重命名、归档和删除。
- 资料导入、处理进度、取消、失败原因和重试。
- SQLite 业务数据库与 LanceDB 嵌入式向量数据库。
- BM25 全文检索、ANN 向量检索、元数据过滤和 RRF 混合排序。
- 带来源定位的流式 RAG 问答。
- 多轮会话与消息持久化。
- OpenAI、Anthropic、Google Gemini 和 Ollama 生成模型。
- 应用内置本地、Ollama、OpenAI、Gemini及 OpenAI 兼容接口的 Embedding。
- 模型连接测试、切换、取消、错误转换和加密凭据。
- 索引状态检查、优化、重建和 Embedding 模型迁移。

### 2.2 支持的资料类型

| 类型 | 输入 | 引用定位 |
|---|---|---|
| 纯文本 | `.txt` 或直接粘贴 | 段落范围 |
| Markdown | `.md` | 标题层级与段落 |
| 网页 | HTTP/HTTPS URL | 页面标题、章节与原始 URL |
| PDF | `.pdf` | 页码与片段 |
| Word | `.docx` | 标题层级、段落与表格位置 |
| PowerPoint | `.pptx` | 幻灯片编号与元素位置 |
| Excel | `.xlsx` | 工作表名称与单元格范围 |
| CSV | `.csv` | 行范围 |

DOCX 的分页依赖具体排版引擎，文件本身不提供稳定页码，因此引用不得伪造页码。XLSX 读取工作簿内已有的缓存值和公式文本，不在应用内实现完整 Excel 公式计算引擎。

### 2.3 不包含

- `.doc`、`.ppt`、`.xls` 等旧版二进制 Office 格式。
- 播客、TTS、STT 和音视频处理。
- 笔记、摘要模板、自定义转换和洞察。
- 云同步、多人协作、账号系统和服务器部署。
- 移动端、macOS 和 Linux。
- 插件市场和自动模型路由。

## 3. 技术架构

### 3.1 桌面外壳

- Electron 提供 Windows 桌面窗口与系统集成。
- React + TypeScript 构建渲染层界面。
- Electron 主进程承担本地后端职责，不启动独立 HTTP API 服务。
- 预加载脚本通过白名单 IPC 向渲染层暴露业务命令。
- 文件解析、Embedding 和索引构建在 Worker Threads 中运行，避免阻塞主进程和界面。
- NSIS 生成 Windows x64 安装程序。

### 3.2 进程边界

#### 渲染进程

负责页面展示、交互状态、流式文本渲染和国际化。渲染进程不能直接访问 Node.js、文件系统、数据库或系统凭据。

#### 预加载桥接

只公开经过版本化定义的命令和事件。所有输入、输出与错误均使用运行时 Schema 校验。取消任务和停止生成使用显式取消标识。

#### 主进程

负责业务服务、窗口生命周期、数据目录、SQLite、LanceDB、凭据、模型 Provider、任务编排和结构化日志。

#### 工作线程

负责不可信或计算密集型任务，包括文件解析、网页清理、文本分块、批量 Embedding、LanceDB 写入、索引创建、优化和重建。

## 4. 组件设计

### 4.1 项目服务

管理研究项目的创建、更新、归档和删除。删除项目采用可恢复状态，完成其资料、文件和向量清理后再最终移除。

### 4.2 资料摄入服务

统一处理文本、URL 与文件输入：

1. 验证输入类型、文件签名、大小与路径。
2. 将本地文件原子复制到应用管理的数据目录。
3. 在 SQLite 创建来源、内容版本与后台任务。
4. 由对应解析器提取结构化文本和定位信息。
5. 根据内容结构分块并生成稳定内容哈希。
6. 使用当前 Embedding Space 批量生成向量。
7. 写入 LanceDB 并建立或更新检索索引。
8. 完成校验后将来源标记为可搜索。

解析器必须保留能够回到原始资料的位置：PDF 页码、PPTX 幻灯片、XLSX 工作表与单元格范围、DOCX 标题/段落/表格、Markdown 标题以及 URL 章节。

首版使用以下明确的安全与分块默认值：单个本地文件最大 100 MB；网页下载正文最大 10 MB、最多跟随 5 次重定向、单次请求超时 30 秒。普通连续文本以约 400 Token 为目标块大小、60 Token 重叠、少于 80 Token 的尾块并入前块。Markdown 与 DOCX 优先按标题和段落边界切分；PDF 优先保持页边界；PPTX 以幻灯片为基本单元，超长幻灯片再按段落切分；XLSX 与 CSV 按工作表和连续非空行区域切分，保留表头并记录单元格或行范围。以上参数作为内部版本化策略保存，改变策略时创建新的索引版本，而不直接混用旧块。

### 4.3 检索服务

检索限定在当前项目与当前有效内容版本：

1. 使用当前 Embedding 模型生成查询向量。
2. 并行执行向量召回与 BM25 召回。
3. 应用项目、来源和版本元数据过滤。
4. 使用 Reciprocal Rank Fusion 合并排名。
5. 按来源与内容哈希去重。
6. 回到 SQLite 校验有效内容版本并补充引用元数据。
7. 输出有限数量、带分数和位置的上下文片段。

### 4.4 RAG 与会话服务

RAG 服务将检索片段按 Token 预算组装为上下文，加入不可忽略的引用标识，并调用用户选定的生成模型。模型输出通过统一事件流传给渲染层；用户可以停止生成。最终消息与引用关系写入 SQLite。

生成模型只接收检索出的必要片段，不接收整份资料。切换生成模型不影响现有向量索引。

### 4.5 任务服务

任务状态为：

`queued → running → completed | failed | cancelled`

任务记录保存类型、业务对象、进度、尝试次数、可重试标志、截断后的错误信息和时间戳。仅网络错误、限流和部分服务端错误自动退避重试；认证、配置、格式和校验错误不自动重试。

应用异常退出后，启动恢复流程检查 `running` 任务，并根据任务幂等键恢复或标记为可重试。

## 5. 数据设计

### 5.1 SQLite：业务事实来源

主要实体：

- `projects`
- `sources`
- `source_revisions`
- `conversations`
- `messages`
- `message_citations`
- `model_profiles`
- `credentials`
- `tasks`
- `embedding_spaces`
- `app_settings`

所有业务实体具有创建时间、更新时间与版本字段。迁移按顺序编号，启动时自动执行；迁移失败时停止启动并提供恢复入口。迁移前使用 SQLite Backup API 生成备份，滚动保留最近三个版本。

### 5.2 LanceDB：可重建检索数据

每条检索记录至少包含：

- `chunk_id`
- `project_id`
- `source_id`
- `source_revision_id`
- `embedding_space_id`
- `chunk_order`
- `locator_type` 与 `locator_value`
- `text`
- `content_hash`
- `language`
- `vector`
- `created_at`

LanceDB 保存分块文本是为了同时支持 BM25 和向量检索。SQLite 原文和应用管理的原始文件能够完整重建 LanceDB；LanceDB 不作为不可恢复业务数据的唯一存储位置。

### 5.3 Embedding Space

一个 Embedding Space 固定以下属性：

- Provider 类型与配置引用。
- 模型名及模型版本。
- 向量维度。
- 距离算法，默认余弦距离。
- 文档与查询预处理规则版本。
- 分块规则版本。
- 创建时间、健康状态与当前向量数量。

不同模型、不同维度或不兼容版本不得共用同一向量空间。

切换 Embedding 模型时：

1. 创建新的 Embedding Space。
2. 在后台重新生成所有有效来源的向量。
3. 创建 ANN、FTS 与必要元数据索引。
4. 执行数量、一致性和试查校验。
5. 原子更新 SQLite 中的当前 Space 引用。
6. 保留旧 Space 直到切换成功，再异步清理。

检索候选返回后必须用 SQLite 的有效内容版本再次校验，因此跨 SQLite 与 LanceDB 的短暂非事务窗口不会让旧内容进入最终回答。

## 6. 模型兼容设计

### 6.1 统一接口

生成模型接口提供：

- 连接测试。
- 模型名配置与可选发现。
- 流式对话。
- 请求取消。
- Token/用量信息。
- 统一错误分类。

Embedding 接口提供：

- 连接测试。
- 文档批量向量化。
- 查询向量化。
- 维度与限制探测。
- 输入预处理规则。
- 统一错误分类。

### 6.2 Provider 范围

- OpenAI：生成与 Embedding。
- OpenAI 兼容服务：可配置 Base URL、模型名与 API Key，支持生成和/或 Embedding。
- Anthropic：Claude 生成模型。Anthropic 没有自有 Embedding 模型。
- Google Gemini：生成与 Embedding。
- Ollama：本机生成与 Embedding。
- 应用内置本地 Embedding：中英文多语言 ONNX 模型，按需下载并验证文件哈希。

生成模型配置与 Embedding 配置完全解耦。切换生成模型无需重建索引；切换 Embedding 配置必须创建新 Space。

### 6.3 凭据

API Key 通过 Electron `safeStorage` 使用 Windows DPAPI 加密。数据库只保存加密载荷和非敏感元数据。日志、错误提示、诊断导出和 IPC 不得包含明文密钥或认证请求头。

## 7. 界面与交互

### 7.1 页面结构

- 首次启动：语言、生成模型和 Embedding 配置，可跳过模型配置。
- 主窗口左侧：项目列表、新建、重命名、归档和删除。
- 主窗口上方：资料卡片、导入入口和处理进度。
- 主窗口中部：多轮对话、流式回答、停止、复制和重新生成。
- 主窗口右侧：来源引用、定位信息、原文片段与打开原始资料。
- 底部输入区：模型选择、输入框、附件入口和发送。
- 设置中心：通用、语言、主题、生成模型、Embedding、数据目录、索引状态和重建。

界面必须覆盖首次启动、空项目、处理中、处理失败、索引不可用、模型不可用、无检索结果和离线状态。

### 7.2 视觉审批门槛

所有页面和重要状态遵循以下流程：

`页面需求 → 高保真设计图 → 用户确认 → 前端编码 → 运行截图对照 → 修改与验收`

未经用户确认设计图，不开始对应页面的前端编码。总体布局或关键交互发生变化时，重新提交设计图确认。

已选定的总体视觉方向为第一张 Electron 概念图：温暖浅色表面、克制的靛蓝强调色、左侧项目导航、中部资料与对话、右侧引用面板。深色主题在保持信息层级的前提下使用相同布局。

## 8. 安全与可靠性

- Electron 开启上下文隔离与沙箱，关闭渲染进程 Node.js 集成。
- 所有 IPC 输入输出执行运行时校验。
- URL 导入只接受 HTTP/HTTPS，限制重定向、响应大小和超时，不携带浏览器 Cookie。
- 文件采用扩展名与内容签名双重预检，使用唯一名称和原子写入。
- PDF 和 Office 文档在工作线程解析，不执行脚本、宏或外部对象。
- 模型返回的 Markdown 经过清理，不执行任意 HTML、脚本或远程资源。
- 对外错误信息隐藏内部堆栈并限制长度；本地诊断日志使用请求与任务关联 ID。
- 删除、重建、迁移和模型切换均设计为可恢复操作。
- 数据目录缺失、磁盘空间不足、数据库锁定或索引损坏时，应用显示可操作的恢复信息而不是静默失败。

## 9. 测试策略

### 9.1 单元测试

- 各格式解析结果与引用定位。
- 文本分块、内容哈希和 Token 预算。
- RRF 融合、去重与有效版本过滤。
- Provider 错误映射与重试分类。
- 任务状态机和恢复规则。
- IPC Schema 与安全边界。

### 9.2 集成测试

- 空库迁移与旧版本升级。
- SQLite Backup 和恢复。
- LanceDB 建库、写入、删除、检索、优化和重建。
- Embedding Space 后台迁移与失败回滚。
- 资料删除和跨数据库一致性修复。
- 使用固定样本测试 TXT、MD、URL、PDF、DOCX、PPTX、XLSX 和 CSV。

### 9.3 Provider 契约测试

OpenAI、OpenAI 兼容、Anthropic、Gemini 和 Ollama 适配器共享一套生成模型契约；本地、Ollama、OpenAI、Gemini 与兼容接口共享一套 Embedding 契约。自动测试使用模拟服务，真实连接使用手动冒烟测试，避免测试套件依赖付费密钥。

### 9.4 桌面与全链路测试

- Electron 自动化覆盖首次启动、模型配置、项目管理、导入、对话、引用和语言切换。
- 固定测试链路覆盖“导入 → 解析 → 向量化 → 混合检索 → 回答 → 引用定位”。
- Windows x64 验证全新安装、覆盖升级、卸载和保留用户数据。
- 每个前端页面使用实际运行截图与已批准设计图进行人工对照验收。

## 10. 错误处理原则

- 用户输入错误：立即显示具体字段和修复方法。
- 不支持格式：明确列出支持格式，不创建处理任务。
- 永久处理错误：保存失败状态与可读原因，不自动重试。
- 临时网络错误：指数退避并加入随机抖动，达到上限后允许手动重试。
- 服务商限流：保留任务进度，显示稍后重试状态。
- 磁盘或数据库错误：停止后续写入，避免产生更多不一致数据。
- LanceDB 错误：继续保留 SQLite 原文和原始文件，提供检查与重建入口。
- 流式生成中断：保存已完成文本并允许重新生成。

## 11. 首版验收标准

在一台未安装开发工具的 Windows x64 电脑上，用户能够：

1. 通过 `.exe` 安装并启动 MyNotebookLM。
2. 在中文和英文之间切换。
3. 配置四类生成模型中的任意一种，并配置本地或云端 Embedding。
4. 创建研究项目并导入所有首版支持的资料格式。
5. 在界面观察处理进度，对失败任务执行重试。
6. 对资料提问并获得流式回答。
7. 从回答引用定位到 PDF 页码、幻灯片、工作表单元格、Word 段落或网页章节。
8. 关闭并重新启动应用后继续访问项目、索引和会话。
9. 切换 Embedding 模型并在后台完成无损索引迁移。
10. 在索引损坏时从业务数据重建检索库。

任何对应页面在进入实现前都必须已有用户确认的高保真设计图。
